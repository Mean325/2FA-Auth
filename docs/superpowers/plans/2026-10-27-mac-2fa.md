# macOS 验证器 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 做出 macOS 15+ 的菜单栏验证器：本机离线出码，CloudKit 只同步密文，界面默认简体中文并可切换英文。

**Architecture:** SwiftUI 的 `MenuBarExtra` 负责复制，主窗口负责添加、删除、导入和设置。`OTPEngine` 纯计算。展示字段在 SwiftData，密钥在不可同步的钥匙串，整包账号用 AES-GCM 后写入 CloudKit 私有库 `VaultZone`。同步钥匙放在可同步的 iCloud 钥匙串。文案全部走 `Localizable.xcstrings`，源语言 `zh-Hans`，第一版内置 `en`。

**Tech Stack:** Swift 5 / SwiftUI、SwiftData、CloudKit、CryptoKit、Vision、LocalAuthentication、String Catalog。Stitch 项目 `projects/10337349734490332363`。

**执行约束：** 代理只做静态编译（`swift build` 或 `xcodebuild ... build`），不运行测试。测试代码写进仓库，由用户自己运行。没有用户明确要求时不执行 `git commit`。下面的提交步骤保留给用户点名之后。

- [ ] **Step 2: 实现引擎**

```swift
import CryptoKit
import Foundation

public enum OTPKind: String, Codable, Sendable { case totp, hotp, steam }
public enum OTPAlgorithm: String, Codable, Sendable { case sha1, sha256, sha512 }

public enum OTPEngine {
    public static let steamAlphabet = Array("23456789BCDFGHJKMNPQRTVWXY")

    public static func code(secret: Data, kind: OTPKind, algorithm: OTPAlgorithm, digits: Int, period: Int, counter: UInt64, at unixTime: TimeInterval) -> String {
        let moving: UInt64
        switch kind {
        case .hotp:
            moving = counter
        case .totp, .steam:
            let step = UInt64(max(period, 1))
            moving = UInt64(unixTime) / step
        }
        let binary = truncated(hmac(algorithm, key: secret, counter: moving))
        if kind == .steam { return steam(binary) }
        let modulus = UInt32(pow10(max(digits, 1)))
        return String(format: "%0\(digits)u", binary % modulus)
    }

    /// 剩余不足 5 秒时，界面要显示并复制下一条。HOTP 不使用这个时间。
    public static func displayTime(kind: OTPKind, period: Int, at unixTime: TimeInterval) -> TimeInterval {
        guard kind != .hotp else { return unixTime }
        let step = TimeInterval(max(period, 1))
        let into = unixTime.truncatingRemainder(dividingBy: step)
        let remaining = into == 0 ? step : step - into
        return remaining <= 5 ? unixTime + remaining : unixTime
    }

    private static func hmac(_ algorithm: OTPAlgorithm, key: Data, counter: UInt64) -> Data {
        var big = counter.bigEndian
        let message = Data(bytes: &big, count: 8)
        let symmetric = SymmetricKey(data: key)
        switch algorithm {
        case .sha1:
            return Data(HMAC<Insecure.SHA1>.authenticationCode(for: message, using: symmetric))
        case .sha256:
            return Data(HMAC<SHA256>.authenticationCode(for: message, using: symmetric))
        case .sha512:
            return Data(HMAC<SHA512>.authenticationCode(for: message, using: symmetric))
        }
    }

    private static func truncated(_ hmac: Data) -> UInt32 {
        let offset = Int(hmac[hmac.count - 1] & 0x0f)
        let slice = hmac.subdata(in: offset..<(offset + 4))
        let value = slice.reduce(UInt32(0)) { ($0 << 8) | UInt32($1) }
        return value & 0x7fff_ffff
    }

    /// 先取出的余数是第一位，和 Steam 客户端一致。
    private static func steam(_ value: UInt32) -> String {
        var rest = Int(value)
        return String((0..<5).map { _ in
            let index = rest % steamAlphabet.count
            rest /= steamAlphabet.count
            return steamAlphabet[index]
        })
    }

    private static func pow10(_ digits: Int) -> Int {
        (0..<digits).reduce(1) { total, _ in total * 10 }
    }
}
```

- [ ] **Step 1: 解码规则**

Base32 去掉空格、连字符，不区分大小写，填充符可缺。Steam 手动输入：40 位十六进制按十六进制；否则先 Base32，失败再 Base64。`otpauth` 缺省算法 SHA1、位数 6、周期 30、HOTP 计数器 0。发行者是 Steam（不区分大小写）时，类型记为 `.steam`。

```swift
public struct DraftAccount: Equatable, Sendable {
    public var issuer: String
    public var account: String
    public var secret: Data
    public var kind: OTPKind
    public var algorithm: OTPAlgorithm
    public var digits: Int
    public var period: Int
    public var counter: UInt64
}
```

`SecretCodec.base32` 按 RFC 4648 解码，忽略空格和连字符，不区分大小写，允许缺少填充。`steamManual` 对 40 位十六进制走十六进制，否则先 Base32，再 Base64。`OtpauthParser.parse` 读取 `otpauth://`：缺省算法 SHA1、位数 6、周期 30、HOTP 计数器 0；`issuer` 优先于路径里冒号前的服务名；发行者是 Steam（不区分大小写）时 `kind` 为 `.steam`。

测试必须通过这两条：`otpauth://totp/GitHub:ada?secret=JBSWY3DPEHPK3PXP` 得到服务名 GitHub、账号 ada、SHA1、6 位、30 秒；`issuer=Steam` 的 totp 链接得到 `.steam`。`JBSWY3DPEHPK3PXP` 无填充也要解出字节。

```swift
public struct VaultRecord: Equatable, Sendable {
    public var id: UUID
    public var issuer: String
    public var account: String
    public var secret: Data
    public var kind: OTPKind
    public var algorithm: OTPAlgorithm
    public var digits: Int
    public var period: Int
    public var counter: UInt64
    public var pinned: Bool
    public var updatedAt: Date
    public var deletedAt: Date?
}

public enum VaultMerge {
    public static func merge(local: VaultRecord, remote: VaultRecord) -> VaultRecord {
        let localDead = local.deletedAt != nil
        let remoteDead = remote.deletedAt != nil
        if localDead || remoteDead {
            if local.updatedAt == remote.updatedAt { return localDead ? local : remote }
            return local.updatedAt > remote.updatedAt ? local : remote
        }
        var winner = local.updatedAt >= remote.updatedAt ? local : remote
        let counter = max(local.counter, remote.counter)
        winner.counter = counter
        winner.updatedAt = max(local.updatedAt, remote.updatedAt)
        return winner
    }
}
```

测试三条：较新的墓碑盖过旧修改；更新时间相同则墓碑获胜；两边都有效时计数器取较大值，其余字段来自较新记录。

### Task 7: 本机存储、加密和同步

**Files:**
- Create: `App/AccountStore.swift`
- Create: `App/VaultCrypto.swift`
- Create: `App/CloudSync.swift`
- Create: `App/TwoFA.entitlements`

- [ ] **Step 1: 钥匙串与 SwiftData**

SwiftData 的 `AccountEntity` 不含密钥。密钥用 `kSecClassGenericPassword`，`kSecAttrService = app.2famac.account`，`kSecAttrAccount` 为小写 UUID，`kSecAttrSynchronizable = false`，`kSecAttrAccessible = kSecAttrAccessibleAfterFirstUnlock`。先写钥匙串，再写 SwiftData；后者失败则删除刚写的钥匙串项。

同步钥匙服务名 `app.2famac.sync`，账户名 `vault-key`，`kSecAttrSynchronizable = true`。创建时机按设计说明第 5.3 节：等待云端钥匙时不添加；空库第一次添加且钥匙串同步可用时才创建；钥匙串同步关闭时只写本机。

- [ ] **Step 2: AES-GCM**

账号密文的认证数据是 UUID 的 16 字节。偏好记录认证数据是 UTF-8 `settings`。`schemaVersion` 明文为 1，大于 1 的记录计入「暂时打不开」，不覆盖本机。密文包里的密钥字段用标准 Base64。

- [ ] **Step 3: CloudKit**

容器 `iCloud.app.2famac`，私有库，自定义区 `VaultZone`。记录类型 `VaultItem` 与 `Preference`。用变更令牌增量拉取，令牌失效则重拉整区。合并调用 `VaultMerge.merge`。上传失败不回滚本机，2 秒起步退避，最长 5 分钟。iCloud 未登录、钥匙串未开、等待钥匙、解密失败的文案使用「界面文案」表，菜单栏不弹同步错误。

- [ ] **Step 4: 权限**

`TwoFA.entitlements` 打开 iCloud 与 CloudKit，容器标识 `iCloud.app.2famac`。没有开发者账号时，编译可以先不签名该容器，但代码里的容器标识保持这个值。

- [ ] **Step 5: 静态编译并提交**

Run: `xcodebuild -project TwoFA.xcodeproj -scheme TwoFA -destination 'platform=macOS' build`

仅当用户要求提交时执行。`git commit -m "feat: 用钥匙串和 CloudKit 密文同步账号"`
